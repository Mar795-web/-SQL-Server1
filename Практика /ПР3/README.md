Практические задания по транзакциям и блокировкам в SQL Server.

Уровни изоляции транзакций

• READ UNCOMMITTED — допускает чтение незакоммиченных данных; возможно грязное чтение.
• READ COMMITTED — не позволяет читать незакоммиченные данные, но результат повторного чтения может измениться после фиксации другой транзакции.
• REPEATABLE READ — защищает уже прочитанные строки от изменения до завершения транзакции.
• SNAPSHOT — позволяет читать согласованную версию данных, что удобно, например, для отчётов во время изменения данных.

Блокировки

• Транзакции (COMMIT / ROLLBACK). SQL Server устанавливает блокировки при изменении данных; после завершения транзакции блокировки снимаются.
• UPDLOCK. Запрашивает блокировку обновления для выбранных строк, помогая избежать конфликтов при последующем изменении.
• TABLOCKX. Устанавливает эксклюзивную блокировку таблицы, из-за которой другие сессии не могут выполнять конфликтующие операции.
• Эскалация блокировок. При большом количестве блокировок SQL Server может заменить множество мелких блокировок более крупной, например табличной. Это уменьшает накладные расходы, но может снизить параллельность.
• Поиск блокирующих сессий. Системные представления SQL Server позволяют определить, какая сессия удерживает блокировку и какая ожидает её освобождения.

Используемые технологии

• Microsoft SQL Server
• Transact-SQL (T-SQL)
• Индексы и планы выполнения запросов
• Транзакции, уровни изоляции и блокировки
